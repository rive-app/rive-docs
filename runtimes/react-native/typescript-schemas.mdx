<Note>
  TypeScript schema generation requires the new React Native runtime, `@rive-app/react-native` 0.5.0 or later. See the [migration guide](/runtimes/react-native/migration-guide) to upgrade.
</Note>

`@rive-app/react-native` can generate TypeScript schemas for your `.riv` files, so that artboard names, state machine names, view model names, property paths, and enum values are all checked at compile time. A typo in any of them becomes a TypeScript error instead of a runtime failure, and your editor autocompletes them.

Schemas are opt-in per asset. Generate one for an asset and you get autocomplete and compile-time checking everywhere that asset is used; load the asset with `require(...)` instead and it keeps accepting plain strings. You can adopt this one file at a time.

A schema is a `.d.ts` declaration file, so nothing is added to your bundle and no runtime code changes.

## Quick start

<Steps>
  <Step title="Install the introspection dependency">
    ```bash
    npm install --save-dev @rive-app/canvas
    # or for Yarn
    yarn add -D @rive-app/canvas
    ```

    The generator uses Rive's WASM runtime, version 2.39 or later, to inspect `.riv` files. It's only needed on the machine running codegen and is never bundled into your app.
  </Step>
  <Step title="Generate a schema next to each asset">
    ```bash
    npx rive-gen-types assets/rive/rewards.riv     # one file → rewards.riv.d.ts
    npx rive-gen-types --all assets/rive           # every .riv in a directory
    ```

    This writes a `rewards.riv.d.ts` file next to the asset. Commit these files. They're deterministic and human-readable, and regenerating produces identical output for an unchanged asset.
  </Step>
  <Step title="Import and use the asset">
    Importing a `.riv` file requires `riv` in Metro's `assetExts`. See [loading Rive files](/runtimes/react-native/loading-rive-files) for the setup.

    ```tsx
    import { useRiveFile } from '@rive-app/react-native';
    import rewardsRiv from './assets/rive/rewards.riv';

    const { riveFile } = useRiveFile(rewardsRiv);
    ```

    Everything in the next section is now compile-checked.
  </Step>
</Steps>

## What gets typed

A generated schema looks like this:

```ts rewards.riv.d.ts
// Generated by rive-gen-types — do not edit manually. @generated
/* eslint-disable */
// Source: rewards.riv
import type { RiveFileSource } from '@rive-app/react-native';
declare const asset: RiveFileSource<{
  schemaVersion: 1;
  artboards: 'Main' | 'Lives 2' | 'Item Value' | 'Chest' | 'Button' | 'Heart' | 'Item';
  defaultArtboard: 'Main';
  stateMachines: {
    'Main': 'State Machine 1';
    // ...one entry per artboard
  };
  enums: {
    Item_Selection: 'Coin' | 'Gem';
  };
  viewModels: {
    Rewards: {
      Price_Value: 'number';
      Coin: 'viewModel:Item_Icon_Value';
      // ...
    };
    Item: {
      Item_Selection: 'enum:Item_Selection';
    };
    // ...
  };
  referencedAssets: {};
}>;
export default asset;
```

- `schemaVersion` is the format version of the schema. If a schema doesn't match the installed runtime, the import reports that it's out of date.
- `enums` lists the file's enums by name. An enum property refers to one with `enum:Name`, as `Item_Selection: 'enum:Item_Selection'` does above. The values are the enum's keys, not its display labels.
- `referencedAssets` lists the assets that aren't embedded in the file, which your app must supply. See [referenced assets](#referenced-assets).

Everything flows from the import, with no manual type annotations.

Artboard and state machine names are constrained to the file's contents. `riveFile` is typed once it has loaded:

```tsx
if (!riveFile) return null;

return (
  <RiveView
    file={riveFile}
    artboardName="Main"                  // ✓ autocompletes; "Mian" is an error
    stateMachineName="State Machine 1"   // ✓ constrained to Main's state machines
  />
);
```

View model names are constrained:

```tsx
const { instance } = useViewModelInstance(riveFile, {
  viewModelName: 'Rewards',              // ✓ 'Rewrads' is a compile error
  async: true,
});
```

Property paths are constrained per kind, including nested paths:

```tsx
const { value, setValue } = useRiveNumber('Price_Value', instance);   // ✓
useRiveNumber('Coin/Item_Value', instance);                           // ✓ nested
useRiveNumber('Coin', instance);         // ✗ Coin is a view model ref, not a number
useRiveTrigger('Price_Value', instance); // ✗ wrong kind
```

Enum values are exact unions, resolved through the schema's `enums`:

```tsx
const { value: kind, setValue: setKind } = useRiveEnum(
  'Item_Selection/Item_Selection',
  instance
);
// kind: 'Coin' | 'Gem' | undefined

setKind('Gem');       // ✓
setKind('Diamond');   // ✗ compile error
```

To use an enum's values in your own types, use `EnumValues`:

```ts
import { type EnumValues } from '@rive-app/react-native';
import rewardsRiv from './assets/rive/rewards.riv';

type ItemKind = EnumValues<typeof rewardsRiv, 'Item_Selection'>; // 'Coin' | 'Gem'
```

Instance accessors are typed the same way. The instance is undefined until it has loaded:

```ts
instance?.numberProperty('Coin/Item_Value');                          // ✓
instance?.enumProperty('Item_Selection/Item_Selection')?.set('Gem');  // ✓ typed values

const coin = await instance?.viewModelAsync('Coin');                  // ✓ typed nesting
coin?.numberProperty('Item_Value');                                   // ✓
```

### Referenced assets

Assets that aren't embedded in the file, whether referenced or hosted, appear in `referencedAssets`, keyed by the asset's unique name. Generate a schema and the `referencedAssets` option of `useRiveFile` is checked against them:

```tsx
import { useRiveFile } from '@rive-app/react-native';
import outOfBandRiv from './assets/rive/out_of_band.riv';

// The schema contains: referencedAssets: { 'Inter-594377': 'font'; ... }
const { riveFile } = useRiveFile(outOfBandRiv, {
  referencedAssets: {
    'Inter-594377': { source: require('./assets/Inter.ttf'), type: 'font' }, // ✓
  },
});
```

An unknown key is a compile error, and so is a `type` that doesn't match the asset. If the file has no referenced assets, any entry is an error. See [loading assets](/runtimes/react-native/loading-assets) for the ways to supply an asset.

## Typing your own components

Use `TypedRiveFile` and `TypedViewModelOf` to keep type safety across component boundaries:

```tsx
import {
  useRiveNumber,
  type TypedRiveFile,
  type TypedViewModelOf,
} from '@rive-app/react-native';
import rewardsRiv from './assets/rive/rewards.riv';

function RewardsScreen({ file }: { file: TypedRiveFile<typeof rewardsRiv> }) {
  // artboardName, viewModelName, and paths are still checked here
}

function PricePanel({
  instance,
}: {
  instance: TypedViewModelOf<typeof rewardsRiv, 'Rewards'>;
}) {
  const { value } = useRiveNumber('Price_Value', instance);
  // ...
}
```

## Typing files loaded from a URL

A `.riv.d.ts` file only types a local import. For a file loaded from a URL, generate a standalone schema with `--out`, then pass the type explicitly:

```bash
npx rive-gen-types https://example.com/rewards.riv --out src/rive/rewards-schema.ts
```

```tsx
import { RiveFileFactory, useRiveFile } from '@rive-app/react-native';
import type { RewardsSchema } from './rive/rewards-schema';

const url = 'https://example.com/rewards.riv';

const { riveFile } = useRiveFile<RewardsSchema>({ uri: url });

// Or, outside of a component:
const file = await RiveFileFactory.fromURL<RewardsSchema>(url, undefined);
```

The output is a plain `.ts` file that exports the schema as a type. The type is named after the input file (`rewards.riv` → `RewardsSchema`). Use `--name` to choose a different name.

## Workflow

- **Regenerate after editing a `.riv` in the Rive Editor**, then fix whatever TypeScript now flags. Renamed artboards, removed properties, and changed enum values all surface as compile errors at the exact call sites.
- **Commit the `.riv.d.ts` files** alongside the assets.
- **Optionally guard in CI** to fail the build when schemas drift out of sync:

```yaml
- name: Validate .riv schemas
  run: |
    npx rive-gen-types --all assets/rive
    if [ -n "$(git status --porcelain -- 'assets/rive/*.riv.d.ts')" ]; then
      echo ".riv.d.ts files are out of date — run 'npx rive-gen-types --all assets/rive' and commit."
      exit 1
    fi
```

## Behavior and limits

- **Files without a schema stay untyped.** Files loaded with `require(...)`, from a URL, or through `RiveFileFactory` accept any string everywhere, unless you pass them a schema. Type safety is opt-in per asset.
- **Files without view models** still get typed artboard and state machine names.
- **Nested paths are typed up to two hops** (`'a/b/leaf'`). Deeper paths are valid at runtime but need an untyped instance or a cast.
- **Dynamic paths.** A typed instance intentionally rejects `string` variables as paths. If you build paths at runtime, keep the instance untyped for those call sites.
- **List elements are untyped** (`ViewModelInstance`) because a `.riv` schema can't know which view model a list holds at a given index.
- **Artboard properties are untyped.** `artboardProperty` accepts any path.
- **Built-in enums are untyped.** Only enums defined in the file get a named entry. A property that uses a built-in enum is typed `enum` and accepts any string.
- **Nested view models need a default instance.** The generator reads a nested view model's name from the default instance. Without one, the property is typed `viewModel`, and its nested paths aren't typed.

## CLI reference

```bash
npx rive-gen-types <path>                                # writes <file>.riv.d.ts next to the asset
npx rive-gen-types <path-or-url> --out <out>             # writes a standalone schema type (required for URLs)
npx rive-gen-types <path-or-url> --out <out> --name <n>  # sets the name of the schema type
npx rive-gen-types --all <directory>                     # every .riv in a directory, recursively
```

The exit code is non-zero if any file fails, for example a corrupt file, a file with no artboards, or a missing `@rive-app/canvas`. With `--all`, the generator processes every file and reports each failure.

## Troubleshooting

<AccordionGroup>
  <Accordion title="rive-gen-types needs '@rive-app/canvas' …">
    Install the dev-time introspection dependency:

    ```bash
    npm install --save-dev @rive-app/canvas
    # or for Yarn
    yarn add -D @rive-app/canvas
    ```
  </Accordion>
  <Accordion title="An import reports 'Cannot find module', or is typed as number">
    Check that a `.riv.d.ts` file exists next to the asset, and that its name matches the `.riv` file. Without one, TypeScript has no declaration for the import, or falls back to any `declare module '*.riv'` in your project.
  </Accordion>
  <Accordion title="An import reports 'This .riv.d.ts is out of date'">
    The schema was generated in a format your installed `@rive-app/react-native` doesn't accept. Regenerate it with `npx rive-gen-types`.
  </Accordion>
  <Accordion title="Names stopped compiling after editing the file">
    The `.riv` file no longer matches your code. Regenerate the schema with `npx rive-gen-types …` and follow the compile errors to every call site that referenced the renamed or removed item.
  </Accordion>
</AccordionGroup>
