By default, Rive logs stay native: Logcat on Android, and React Native's `RCTLog` on iOS. Nothing reaches JavaScript until you call `RiveLog.forwardToConsole()` or `RiveLog.setHandler()`.

On iOS, native errors are logged with `RCTLogError`, so development builds also show a red box. Forwarding logs or setting a handler avoids this.

## Forwarding logs to the console

```ts
import { RiveLog } from '@rive-app/react-native';

RiveLog.forwardToConsole();
```

Messages are prefixed with `[Rive/<tag>]`. Debug and info logs use `console.log`. Warnings and errors both use `console.warn`, so they don't open the error overlay in development. Errors you can handle reach your app through `onError` and rejected promises. See [Error handling](/runtimes/react-native/error-handling).

## Setting the log level

Messages below the minimum level are dropped, including from the native log. The default is `warn`.

```ts
RiveLog.setLogLevel('debug'); // 'debug' | 'info' | 'warn' | 'error'
```

## Using a custom log handler

```ts
RiveLog.setHandler((level, tag, message) => {
  myLogger.log(level, `[Rive/${tag}] ${message}`);
});
```

Only one handler is active at a time, so `setHandler` and `forwardToConsole` replace each other. Tags differ between iOS and Android, so don't match on specific tags.

## Returning to native logging

Call `RiveLog.resetHandler()` to remove the current handler and send logs back to the native log.
